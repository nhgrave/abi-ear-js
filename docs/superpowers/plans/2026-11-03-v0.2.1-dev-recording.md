# abi-ear-js v0.2.1, gravação em modo local: plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Com `npm run dev`, a página principal grava a sessão compartilhada (quadros, áudio, `session.json`) numa
pasta do PC e lista as gravações; o build publicado não contém nada disso e a rota `/spike/recorder/` deixa de existir.

**Architecture:** Um módulo só de desenvolvimento, `src/dev/recorder/`, carregado pelo `App.vue` com `import()`
dinâmico dentro de `import.meta.env.DEV` (o Vite remove o ramo e o chunk no build). A gravação usa o `MediaStream` que
a página já compartilha, mas captura por conta própria: um clone da trilha de vídeo vai para um worker que tira um
JPEG a cada ~100 ms e escreve na pasta; um `AudioContext` próprio com o worklet da página escreve o WAV em pedaços.
As partes puras (formato, WAV, ritmo dos quadros, histórico, verificação do `dist/`) têm testes; a cola com as APIs
do navegador é fina e passa pelo teste do autor.

**Tech Stack:** Vue 3.5.44, Vite 8, TypeScript 7 (`tsc --noEmit`), Vitest 5 (ambiente node). APIs do Chrome: File
System Access (`showDirectoryPicker`, `createWritable`), IndexedDB, `MediaStreamTrackProcessor`, `OffscreenCanvas`,
AudioWorklet. Nenhuma dependência nova.

**Spec:** `docs/superpowers/specs/2026-11-03-v0.2.1-dev-recording-design.md`.

## Global Constraints

- Nada do gravador no `dist/`: nem o marcador `abi-ear-dev-recorder`, nem `showDirectoryPicker`, nem o texto
  `Gravação (modo local)`, nem arquivo com `recorder` ou `spike` no caminho. O `npm run build` falha se houver.
- Nenhum `import` estático de `src/dev/**` a partir de código de produção; só o `import()` dentro de
  `import.meta.env.DEV` no `App.vue`. Código de `src/dev/**` pode importar de `src/live/**` e `src/engine/**`.
- Formato: subpasta `AAAA-MM-DD-HHMMSS` (hora local do início); `audio.wav` mono 48 kHz float32 (formato 3, cabeçalho
  de 44 bytes); `frames/<epochMs inteiro>.jpg` com JPEG qualidade 0.95; `session.json` com os campos antigos
  (`startedAt`, `userAgent`, `video`, `audio`, `sampleRate: 48000`, `audioStartEpochMs`, `frameIntervalMs: 100`) e os
  novos (`endedAt`, `frames`, `framesSkipped`, `audioSamples`, `source: "abi-ear-js"`, `appVersion`, `displaySurface`).
- Tempos em ms de época no relógio de `performance` (`performance.timeOrigin + performance.now()`): quadro = chegada
  ao worker de gravação; áudio = primeira amostra pelo `getOutputTimestamp()` do contexto do gravador.
- Textos da seção só em português, dentro de `src/dev/` (não entram no `src/i18n.ts`).
- Sem dependências novas. Versão `0.2.1`. A `master` só recebe o merge com `npm test`, `npm run typecheck` e
  `npm run build` passando.
- Nenhum caminho do PC do autor no código ou nos testes.

## Review Focus

1. **Compartilhamento encerrado no meio da gravação** (botão Parar da página ou "Parar de compartilhar" do Chrome): a
   gravação deve salvar sozinha com `endedAt`, uma vez só, mesmo com o `ended` da trilha e o `watch` de `sharing`
   chamando `stop()` juntos. O `stop` devolve sempre a mesma promessa (Task 5), e o roteiro manual 2 do Task 6
   verifica isso. É cola de navegador, sem teste em node.
2. **Escritas de áudio sem `await`** vindas do worklet a cada 4096 amostras: a ordem e as posições no WAV não podem se
   embaralhar. Teste: Task 2, `appends without awaiting keep order`.
3. **Escrita de quadro mais lenta que 100 ms** (disco lento, 1440p): o quadro é pulado e contado, nunca enfileirado
   sem limite. Teste: Task 3, `skips a due frame while the previous write is pending`.
4. **Pasta com outras coisas** (arquivos soltos, subpastas que não são gravações, `session.json` corrompido): o
   histórico ignora o que não é gravação e mostra a corrompida como incompleta. Teste: Task 4,
   `ignores entries that are not recordings` e `a broken session.json is incomplete`.
5. **Permissão da pasta perdida depois de recarregar:** o botão Gravar fica desabilitado até um clique em "Liberar
   pasta". Roteiro manual 3 do Task 6 (IndexedDB e permissões não existem no ambiente node dos testes).

    formato 3, mono, 32 bits.

    `finish` espera a fila, reescreve o cabeçalho na posição 0 com o tamanho real, fecha e devolve o total de amostras.
    O primeiro erro de escrita rejeita o `finish`.

### Task 3: Ritmo dos quadros e worker de gravação

**Files:**
- Create: `src/dev/recorder/frame-recorder.ts`, `src/dev/recorder/frame-recorder.test.ts`,
  `src/dev/recorder/frames.worker.ts`, `src/dev/recorder/protocol.ts`

**Interfaces:**
- Produces (`frame-recorder.ts`): `class FrameRecorder<F> { constructor(d: { intervalMs: number; encode(frame: F):
  Promise<Blob>; write(name: string, data: Blob): Promise<void> }); offer(frame: F, epochMs: number): 'taken' |
  'early' | 'skipped' | 'stopped'; drain(): Promise<{ frames: number; skipped: number; error: string | null }> }`.
  - Abaixo de `intervalMs` desde o último aceito, devolve `early`.
  - Na hora certa mas com uma escrita pendente, devolve `skipped`, conta e marca a hora, para não pular todos os
    quadros seguintes.
  - Senão chama `encode(frame)` na hora e devolve `taken`. O nome do arquivo é `${Math.floor(epochMs)}.jpg`.
  - Depois de um erro, para de aceitar quadros (`stopped`) e guarda a mensagem.
  - O `encode` precisa desenhar o quadro de forma síncrona antes de devolver a promessa, porque quem chama fecha o
    `VideoFrame` logo depois de `offer`.
- Produces (`protocol.ts`): `type FramesIn = { type: 'start'; readable: ReadableStream<VideoFrame>; dir:
  FileSystemDirectoryHandle; intervalMs: number } | { type: 'stop' }` e `type FramesOut = { type: 'progress';
  frames: number; skipped: number } | { type: 'stopped'; frames: number; skipped: number; error: string | null }`.
  O `dir` é a pasta `frames/` da gravação.
- `frames.worker.ts`:
  - Lê o `readable` e calcula `epochMs = performance.timeOrigin + performance.now()` na chegada de cada quadro.
  - Chama `offer` e fecha o quadro.
  - O `encode` desenha num `OffscreenCanvas` e usa `convertToBlob({ type: 'image/jpeg', quality: 0.95 })`.
  - O `write` usa `dir.getFileHandle(name, { create: true }).createWritable()`.
  - Manda `progress` a cada ~1 s. No `stop`, cancela o reader, espera o `drain` e responde `stopped`.
  - Um erro no `offer` também termina a gravação com `stopped`.

  - Task 4: `RecordingSummary`, `summarize`.
  - De `src/live/capture.ts`: `audioTimeMs`, `outputTimestamp`. De `src/live/audio-worklet.ts`: a URL, como no
    `runtime.ts:9`.
- Produces:
  - `runtime.ts`: `stream(): MediaStream | null` no objeto devolvido por `createRuntime`. Devolve
    `live?.stream ?? null` e é a única mudança no runtime.
  - `vite.config.ts`: `define: { __APP_VERSION__: JSON.stringify(<version do package.json>) }`. Em `env.d.ts`,
    `declare const __APP_VERSION__: string`.
  - `recorder.ts`:
    - `recordingSupport(): string | null`. Devolve null quando dá para gravar, ou a frase do que falta:
      `'Este navegador não tem File System Access.'` ou `'Este navegador não tem MediaStreamTrackProcessor.'`.
    - `type RecordingStats = { name: string; startedAtMs: number; frames: number; skipped: number; audioS: number }`
    - `type ActiveRecording = { stats(): RecordingStats; stop(): Promise<RecordingSummary>; done: Promise<string | null> }`.
      A promessa `done` resolve com a mensagem de erro quando a gravação para sozinha por erro, e com null quando
      para pelo `stop`.
    - `startRecording(stream: MediaStream, root: FileSystemDirectoryHandle): Promise<ActiveRecording>`. Ordem:
      1. Cria a subpasta e `frames/`.
      2. Escreve o `session.json` de `startSession`.
      3. Abre o `audio.wav` num `WavWriter`.
      4. Cria um `AudioContext({ sampleRate: 48000 })` próprio com o worklet `capture` e o ganho 0, como no
         `runtime.ts:220-234`. Na primeira mensagem, `audioStartEpochMs = performance.timeOrigin +
         audioTimeMs(frame, outputTimestamp(ctx))`. Cada bloco vai para `append`.
      5. Inicia o worker de quadros com o `readable` de `new MediaStreamTrackProcessor({ track:
         videoTrack.clone() })`, transferido.
      6. Registra `beforeunload` com `preventDefault`.
      7. Escuta `ended` na trilha de vídeo original e, quando ela termina, faz um stop.
      O `stop`:
      - pode ser chamado várias vezes e sempre devolve a mesma promessa;
      - para o worker (`stop` → `stopped`) e fecha o contexto, o clone e o `beforeunload`;
      - faz `finish` do WAV e reescreve o `session.json` com `finishSession`, usando `fallbackEpochMs = startedAtMs`;
      - devolve o `summarize` do arquivo final.
      Um erro do worker ou do WAV termina a gravação: chama o próprio `stop`, salvando o que der, e resolve `done`
      com a mensagem.
