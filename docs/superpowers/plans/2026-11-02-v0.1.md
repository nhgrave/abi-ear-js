# abi-ear-js v0.1 enxuta: plano de implementação

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publicar no GitHub Pages uma primeira versão que qualquer jogador usa pelo link: compartilha a tela com
áudio, escolhe o mapa e o modo, pega as caixas no vendedor e vê no grid espelhado os itens prováveis de cada uma.

**Architecture:** O motor Python é portado para TypeScript módulo por módulo, sem OCR: matcher e escuta de áudio,
grid, rolagem, sessão do vendedor, reorganização e candidatos. A caixa pega vem da seta do cursor desenhada no vídeo,
com a regra validada no protótipo (adendo de 02/11 em `docs/superpowers/spikes/2026-11-02-risk-prototype.md`). Dois
Web Workers (áudio e visão) alimentam um `Controller` na thread principal, e a interface em Vue lê dele um retrato
simples. A paridade com o Python é garantida por um gabarito exportado do repositório abi-ear. O teste de aceitação
é um replay em Node da gravação real `2026-11-02-160053`.

**Tech Stack:** Vue 3.5.44, @vitejs/plugin-vue 6.0.10, Vite 8, TypeScript 7 (só `tsc --noEmit`; os `.vue` não são
checados, ver Global Constraints), Vitest 5, fft.js 4.0.4, jpeg-js 0.4.4 (só nos testes). GitHub Actions e GitHub Pages.

**Spec:** `docs/superpowers/specs/2026-11-02-abi-ear-js-design.md`. Mudanças decididas depois da spec e que este
plano aplica:
- (a) atribuição pelo cursor do vídeo no lugar da caixa sumida (seção 8.3), conforme o resultado do protótipo;
- (b) v0.1 sem OCR, decisão do autor de 02/11: o jogador escolhe mapa e modo, sem modo automático, sem tooltip ou
  preço e sem tabela de rótulos (seções 8.4 e 8.5 ficam para a v0.2 e a v0.3);
- (c) filtro passa-faixa de 1,2 a 8 kHz no matcher (commit abi-ear `88d5f6f`), no lugar do passa-altas da seção 7;
- (d) publicação contínua: cada merge na `master` publica uma versão nova.

## Global Constraints

- Estritamente passivo: "sem injeção de memória, apenas monitoramento externo seguro". A única entrada é o `getDisplayMedia`.
- Nenhum quadro de tela nem trecho de áudio sai do navegador. A página não faz requisição a terceiros: base, sons, ícones e bibliotecas vêm do próprio site.
- Chrome ou Edge no Windows, compartilhando a tela inteira com "compartilhar áudio do sistema". Sem faixa de áudio, ou com janela ou aba, a página explica o motivo e não segue (reaproveitar `streamProblems` de `spike/recorder/format.ts`).
- Processamento de áudio do navegador desligado: `echoCancellation: false`, `noiseSuppression: false`, `autoGainControl: false`, `suppressLocalAudioPlayback: false`, `systemAudio: 'include'`. `AudioContext` a 48000 Hz, mono pela média dos canais (como `spike/recorder/capture-worklet.ts`).
- Uma só base de tempo: milissegundos de `performance.now()`. O tempo de uma amostra de áudio é `epochOfFrame(frame, 48000, getOutputTimestamp(), performance.timeOrigin) - performance.timeOrigin`, recalculado a cada bloco do worklet. O tempo de um quadro é o `performance.now()` no momento do `createImageBitmap(video)`. Foi com essas bases que a janela de 200 a 400 ms foi validada.
- Constantes portadas com os mesmos nomes e valores do Python (`abi_ear/` no commit `88d5f6f`). Diferenças só onde a plataforma obriga, comentadas no código.
- Nenhum pixel fixo além do modelo da seta (que é do cursor do Windows a 100%, não do jogo). O resto é medido em células do grid detectado.
- Sem calibração, sem contas, sem analytics. Só a preferência de mapa/modo e o idioma da página ficam no `localStorage` (com try/catch).
- Página em pt-BR e en. Nomes de itens e de mapas em inglês, como na base.
- Honestidade: sem cursor confiável, a pegada não é atribuída e a página diz isso ("som ouvido, caixa não identificada"). Nunca chutar a caixa.
- TypeScript 7 é o compilador nativo e não tem a API JS que o vue-tsc usa. A checagem de tipos é `tsc --noEmit` nos `.ts`. Os componentes `.vue` ficam finos, e a lógica vai para módulos `.ts` testados.
- Versões exatas no `package.json` (sem `^`) para as dependências novas.
- Branch `feat/v0.1`, criada a partir de `spike/risk-prototype`. Merge na `master` só na Task 12.
- Commits terminam com `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Os fixtures em `tests/fixtures/` não vão para o git (sons e quadros do jogo, gravações). Os testes que dependem deles usam `describe.skipIf(!hasFixtures(...))`, e a CI roda sem eles. Antes de cada commit, rode localmente com os fixtures presentes e confira que esses testes rodaram, sem nenhum pulado.

## Review Focus

1. **Outro grid na tela (inventário, mochila, aba "Sell"):** sem rótulos, o app não sabe qual é o grid do vendedor. A busca fica restrita à metade direita da tela, onde o vendedor está, e um grid com célula 10% diferente da do vendedor guardado não troca a sessão. Teste na Task 8: `ignores_a_grid_with_another_pitch_and_keeps_the_session`. Teste na Task 9: `vendor_search_stays_in_the_right_half`.
2. **Cursor sem a seta padrão** (escala diferente de 100%, cursor personalizado, seta escondida pelo jogo): nenhuma pegada pode ser atribuída por engano. O indicador Cursor fica amarelo com a dica. Teste na Task 7: `pickup_with_low_arrow_score_is_not_assigned`. Teste na Task 10: `cursor_indicator_turns_yellow_when_arrow_missing`.
3. **Mouse rápido** (pega e devolve, arrasto curto): com amostras do cursor em caixas diferentes dentro da janela, o resultado é "?". Teste na Task 7: `pickup_while_cursor_moves_between_boxes_is_not_assigned`.
4. **Jogo em tela cheia exclusiva (quadro preto) ou compartilhamento parado pelo usuário:** o indicador Tela fica amarelo com a explicação. Ao parar, a página volta ao início e guarda a sessão. Teste na Task 10: `black_frames_turn_screen_indicator_yellow`.
5. **Áudio fraco** (volume de efeitos baixo): as notas caem abaixo do gatilho. O indicador Áudio fica amarelo com a dica de volume, em vez de perder pegadas em silêncio. Teste na Task 10: `audio_indicator_turns_yellow_on_low_scores_or_near_misses`.
